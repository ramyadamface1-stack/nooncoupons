## Changes in this one release

1. Consistent English-only text **inside** all SVG promotional artwork for the Saudi and UAE markets. Original-language HTML article titles and accessible alt text are preserved.
2. Dynamic coupon and featured artwork canvases now advertise 1600×1000; SVG layouts retain five distinct variants, current owner-approved coupon and country marker.
3. New `v=11` URLs across old R2 rescue, direct published articles, new articles, blog thumbnails, visual renderer and dynamically assembled image sitemaps. This prevents browsers and shared caches from reusing older image artwork after deployment.
4. All 15 latest publication cards get lazy-loaded artwork, while the chronological shortcut remains separate from the full alphabetical R2 archive; archive URLs, publication status and cursor pagination remain unchanged.
5. Five Google Search Console opportunity pages receive concise, evidence-safe English HTML title, description and Open Graph metadata during read-only rendering. Original R2 article bodies, URL paths and canonical links stay intact; no live product price, fixed discount or eligibility claim is invented.
6. English article `<title>` suffix is now English, and updated OG/ImageObject dimensions match the artwork size.
7. Article and blog edge-cache version keys are refreshed only for affected public routes, not admin/API pages or unrelated coupon hubs.

## Additional fixes consolidated on 19 November 2026

8. The live `/saudi/category/mobiles` response was about **217,523 bytes** during a diagnostic curl. Source inspection identified an automatically appended 40-section, 5,000-word formulaic guide on every Arabic commercial landing. The new layer uses four practical expandable sections (typically ~2,000–2,200 Arabic words *for the appended layer*), keeps the existing main content and specialty sections, and removes irrelevant bulk padding. A local standalone simulation of `/saudi/category/mobiles` with no R2 records was ~73,632 bytes **after** all landing and specialty layers. These are different sample conditions, so this is not a measured live reduction.
9. Reconnected `relatedArticlesBlock` to commercial landing rendering. It now uses the existing two-minute bounded public manifest cache, shows at most six articles genuinely matching the market and category/brand/model/comparison, excludes `indexable:false` records and unsafe paths, and does not run an expensive full R2 listing.
10. FAQ blocks choose category-appropriate details (e.g. electronics vs fashion). Previously the generic rotation displayed shoes/garment questions on the Saudi mobiles page. Removed stale hard-coded update dates from static guidance and from structured `dateModified`, which did not represent actual article review time.
11. English product and coupon landing pages now include the final page in `BreadcrumbList` JSON-LD, just like the English category pages. Specific product pages gained a short seller/variant/cart comparison checklist and label Arabic-only brand destinations honestly, without publishing fabricated prices or Product/Offer ratings.
12. Fixed the public R2 manifest single-flight promise: an initial synchronous miss/failure no longer leaves the manifest permanently pinned to an empty result. Concurrency still shares one successful read and reuses a fresh snapshot.

## Final pre-merge conversion and mobile pass (19 November 2026)

13. Arabic category, brand, model and comparison coupon panels previously displayed the code but offered only an outbound Noon link. They now include a dedicated native **copy code** button alongside the official store action. The copy runtime validates the code against the proper market list, counts an analytics success only after the clipboard confirms writing, and leaves the code visible if permission is blocked. No existing approved code was changed.
14. `/en/coupons` previously showed ten mixed codes in one unlabeled list without working native copy buttons. It now has separate **Saudi Arabia** and **UAE** sections, each with its own approved five codes, correct market labels, code details links, copy buttons and an accessible route to the country coupon hub. This avoids implying that a code is valid in the other market.
15. English coupon-copy analytics now records the actual CTA placement (`english_all_coupons`, `english_market_coupon`, `english_market_hub`), rather than labeling every successful copy as a generic market-coupon event.
16. Added an accessible, responsive native `<details>` navigation on Arabic and English commerce pages at widths under 900px. The desktop navigation was previously hidden on mobile, while the sticky CTA was hidden under 620px, leaving no obvious menu. The new menu keeps categories, blog, market selection and coupon/verification routes available without external scripts.
17. Consolidated structured data on Arabic category, brand, model, comparison and directory pages. Previously the base commerce renderer and the landing enhancement each injected their own `BreadcrumbList`, and two different `Organization` entities could appear. Each page now emits **one** canonical `BreadcrumbList` graph with localized labels and explicit parent links, **one** `Organization`, the existing `CollectionPage` linked to the breadcrumb's `@id`, and the relevant `FAQPage`. Regression tests cover four distinct Saudi/UAE route shapes and canonical-tag uniqueness.
18. Arabic `/saudi` and `/uae` market-home coupon buttons no longer show a false success when clipboard access is blocked. They now use the same market-validated asynchronous copy handler as commercial landing pages, acknowledge success only after a confirmed write and track a distinct `arabic_country_hero` event placement. The trust chip now counts the five approved codes **in that market**, not all ten site-wide.
19. The mixed-market `/en/coupons` directory no longer presents Saudi Arabia as the selected country. Its header is neutral and its “Choose market” action scrolls to the actual two-market code list, instead of pointing visitors to a Saudi-specific CTA.
20. Updated the article generation quality audit to accept **1600×1000** featured SVG image attributes as well as the legacy **1200×760** pair, without allowing mismatched dimensions or dropping its descriptive alt/title requirements. The old audit only recognized 1200×760, which could unnecessarily lower the image quality score for newly generated articles; this change does not alter the generation schedule or coupon rules.

### Release blocker requiring the owner's editorial decision

`coupon-registry.js` intentionally sets `OWNER_CATALOG_UPDATED_AT=2026-10-14T05:31:46.000Z` and blocks **new publications** when the approval record is older than **30 days**. On 19 November this makes the new-publication coupon status `coupon_registry_stale` even for otherwise approved codes. Explicit regression tests enforce the policy. This pass did **not** falsify the approval date, override the policy, change any coupon, or enable risky publication. The owner must decide whether to renew the catalog approval record after their own review or deliberately change the policy. This is a potential publishing blocker independent of the SEO/image fixes and independent of GitHub merge.

The connected live Search Console integration could not return site data (`INVALID_ARGUMENT`); the historical owner-supplied export below remains the only verified search-performance source for this audit. Do not infer new indexed-page counts, ranking movement, or live GSC errors from it.
